Audio Transfer

Move a file from one browser’s speaker through the air to another browser’s microphone. Filename, size, session identity, fountain equations, and SHA-256 all travel acoustically—there is no payload upload, relay, pairing server, account, or network data path.

Audible transmission: this tool intentionally plays a modem-like 1.5–6.5 kHz signal. Start at a comfortable device volume, keep speakers away from ears, and stop if the sound is uncomfortable. The waveform targets conservative 0.12 RMS / 0.50 peak before the page’s output gain. Acoustic v2 is plaintext: anyone in earshot with a compatible receiver may recover the file.

Send through the speaker

Files may contain any binary bytes and are limited to 1 MiB. Control packets use robust C0 BPSK. File data becomes 512-byte source blocks and a finite R1 BPSK robust-soliton fountain with about 35% equation overhead, so the receiver can recover from missing equations without a return channel.

What the speaker sends

Manifest and final packets use audible C0 OFDM with BPSK. DATA uses wider audible R1 OFDM with BPSK. Both retain deterministic preambles, training, pilots, K=7 rate-1/2 convolutional coding with soft Viterbi decode, interleaving, duplicated C0 protected headers, and CRC32C. Every physical packet remains below four seconds at the observed 44.1 or 48 kHz context rate.

Integrity and privacy boundary

A receiver locks to one nonzero 128-bit session and one SHA-256 manifest identity. CRC32C-invalid packets never enter the bounded incremental fountain solver; conflicting equations fail the transfer. Progress reaches 100% and the download link appears only after all source blocks solve, the repeated C0 final identity agrees, the exact declared length is assembled, and Web Crypto reproduces the acoustically declared SHA-256.

Local processing only. No payload, metadata, microphone sample, or transfer progress is sent to a server or stored persistently. AudioWorklet, modem Worker, microphone tracks, AudioContext, queues, temporary URLs, and stale callbacks are stopped or revoked on Stop, Reset, tab changes, completion, and page exit.
